How do I approach designing software?
-------------------------------------------
When I approach designing software, I try to start with the bigger picture before worrying about small details. For this project, I focused first on what I wanted the 3D scene to look and feel like before jumping into code. I’ve learned that if I don’t think through structure early, I end up rewriting things later. Planning the layout, lighting, and object placement ahead of time made development smoother and helped me avoid unnecessary changes.

What new design skills did this project help you develop?
----------------------------------------------------------
This project helped me think more spatially. Designing a 3D scene forced me to consider object positioning, scale, lighting, and camera movement all at once. I also became more comfortable breaking larger ideas into smaller components, like separating scene setup from camera controls and object rendering.

What design process did you follow?
--------------------------------------
I followed an iterative process. I would implement a feature, test it visually, then adjust it. Instead of trying to build the entire scene at once, I added objects and lighting step by step. That made debugging much easier and allowed me to improve the scene gradually.

How could these tactics apply to future work?

The same approach applies to almost any software project. Breaking problems into smaller parts and testing as I go prevents major issues later. Iteration also helps refine ideas instead of settling for the first version.

How do I approach developing programs?
----------------------------------------
When developing programs, I try to focus on functionality first and polish second. I make sure the core logic works before improving visuals or optimizing. This mindset helped a lot during this project because graphics can get complicated quickly.

What new development strategies did you use?
---------------------------------------------
Working on a 3D scene pushed me to think more about modular code and separation of concerns. Managing shaders, objects, and camera movement separately kept the project organized. I also relied more on testing small changes frequently instead of making large updates all at once.

How did iteration factor into your development?
--------------------------------------------------
Iteration was huge. Almost every milestone involved tweaking lighting, adjusting object positions, or refining camera controls. Seeing the scene update visually made it easy to identify what needed improvement.

How has your coding approach evolved?
--------------------------------------
Earlier in the course, I focused mostly on getting things to work. By the end, I was thinking more about structure, readability, and long-term maintainability. I feel more confident organizing larger projects now compared to the beginning of the term.

Computer science gives me the ability to build things from ideas. Whether it’s graphics, backend systems, or full-stack applications, the core problem-solving skills transfer everywhere. That flexibility supports my long-term goal of working in software development.
